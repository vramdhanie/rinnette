# Rinnette

A static portfolio website for **Rinnette**, a professional artist. The site presents original artwork in an easy-to-navigate gallery: a featured piece on the home page, a portfolio grid, and an about page. The interface stays in a neutral beige / brown / gray palette so the artwork supplies the colour. Every image fits within a single screen and can be clicked to zoom full-screen.

## Definitions

Key terms used throughout this project and its documentation:

| Term | Definition |
| --- | --- |
| **Static export** | The site is pre-rendered entirely to HTML, CSS, and JavaScript at build time (`output: 'export'`). There is **no server runtime** — Firebase serves plain files. |
| **Client component** | A React component marked `"use client"` that runs in the browser. All interactivity (image zoom, mobile menu) lives in client components. |
| **Artwork** | A single portfolio entry — see the `Artwork` type in [`src/data/portfolio.ts`](src/data/portfolio.ts). Holds the title, medium, year, image path, and alt text. |
| **Lightbox** | The full-screen overlay shown when an image is clicked, implemented by [`ZoomableImage`](src/components/ZoomableImage.tsx). Closes on backdrop click, the × button, or `Escape`. |
| **`out/`** | The build output directory containing the deployable static site. Generated by `npm run build`; never committed. |

## Tech Stack

- **[Next.js 14](https://nextjs.org/)** (App Router) configured for static export — no SSR, no server components at runtime
- **[TypeScript](https://www.typescriptlang.org/)** for type safety
- **[Tailwind CSS](https://tailwindcss.com/)** for styling, with a custom neutral palette
- **[Firebase Hosting](https://firebase.google.com/docs/hosting)** for deployment, automated via GitHub Actions

## Getting Started

Install dependencies and start the development server:

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

### Scripts

| Command | Description |
| --- | --- |
| `npm run dev` | Start the local development server with hot reload. |
| `npm run build` | Build the static site into the `out/` directory. |
| `npm run lint` | Run ESLint over the codebase. |

> **Note:** `npm start` (the default Next.js server) is not used — this is a static site. To preview the production build, serve the `out/` directory with any static file server.

## Managing Content

The site is structured so that adding or updating work requires no code changes beyond data and assets:

1. Add the image file to [`public/images/`](public/images).
2. Add or edit an entry in [`src/data/portfolio.ts`](src/data/portfolio.ts):

   ```ts
   {
     id: "piece-7",
     title: "Morning Light",
     medium: "Oil on canvas",
     year: "2025",
     src: "/images/morning-light.jpg",
     alt: "A sunlit landscape in warm tones",
   }
   ```

3. Replace the placeholder copy in [`src/app/page.tsx`](src/app/page.tsx) and [`src/app/about/page.tsx`](src/app/about/page.tsx) with real text.

The current images in `public/images/` are placeholder SVGs and should be swapped for the real artwork.

## Deployment

Deployment to Firebase Hosting is automated with GitHub Actions:

- **On push to `main`** — [`firebase-hosting-merge.yml`](.github/workflows/firebase-hosting-merge.yml) builds the site and deploys to the live channel.
- **On pull request** — [`firebase-hosting-pull-request.yml`](.github/workflows/firebase-hosting-pull-request.yml) builds the site and deploys to a temporary preview channel.

Both workflows run `npm ci && npm run build` and upload the static `out/` directory. The Firebase project and service-account credential are configured via the `FIREBASE_SERVICE_ACCOUNT_RINNETTE` repository secret.

To deploy manually:

```bash
npm run build
firebase deploy --only hosting
```
