# Rinnette

A static portfolio website for **Rinnette**, a professional artist. The site presents original artwork in an easy-to-navigate gallery: a featured piece on the home page, a portfolio grid, and an about page. The interface stays in a neutral beige / brown / gray palette so the artwork supplies the colour. Every image fits within a single screen and can be clicked to zoom full-screen.

## Definitions

Key terms used throughout this project and its documentation:

| Term | Definition |
| --- | --- |
| **Static export** | The site is pre-rendered entirely to HTML, CSS, and JavaScript at build time (`output: 'export'`). There is **no server runtime** — Firebase serves plain files. |
| **Client component** | A React component marked `"use client"` that runs in the browser. All interactivity (image zoom, mobile menu) lives in client components. |
| **Artwork** | A single portfolio entry, authored as one MDX file in [`content/portfolio/`](content/portfolio). Frontmatter holds the structured fields (title, medium, year, image, …); the body is the artist's write-up. Loaded at build time by [`src/lib/portfolio.ts`](src/lib/portfolio.ts). |
| **MDX** | Markdown with embedded components. Used for artwork write-ups so they can contain multiple paragraphs, blockquotes, and supporting images. Compiled to static HTML at build time. |
| **Lightbox** | The full-screen overlay shown when an image is clicked, implemented by [`ZoomableImage`](src/components/ZoomableImage.tsx). Closes on backdrop click, the × button, or `Escape`. |
| **`out/`** | The build output directory containing the deployable static site. Generated by `npm run build`; never committed. |

## Tech Stack

- **[Next.js 14](https://nextjs.org/)** (App Router) configured for static export — no SSR, no server components at runtime
- **[TypeScript](https://www.typescriptlang.org/)** for type safety
- **[Tailwind CSS](https://tailwindcss.com/)** for styling, with a custom neutral palette
- **[MDX](https://mdxjs.com/)** ([`next-mdx-remote`](https://github.com/hashicorp/next-mdx-remote) + [`gray-matter`](https://github.com/jonschlinkert/gray-matter)) for artwork write-ups, compiled at build time
- **[Firebase Hosting](https://firebase.google.com/docs/hosting)** for deployment, automated via GitHub Actions

## Getting Started

Install dependencies and start the development server:

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

### Scripts

| Command | Description |
| --- | --- |
| `npm run dev` | Start the local development server with hot reload. |
| `npm run build` | Build the static site into the `out/` directory. |
| `npm run lint` | Run ESLint over the codebase. |

> **Note:** `npm start` (the default Next.js server) is not used — this is a static site. To preview the production build, serve the `out/` directory with any static file server.

## Managing Content

Each artwork is **one MDX file** in [`content/portfolio/`](content/portfolio). The
filename (without `.mdx`) is its id and URL — e.g. `piece-7.mdx` →
`/portfolio/piece-7`. Adding or editing work needs no code changes.

To add a piece:

1. Put the main image in [`public/images/`](public/images).
2. Create `content/portfolio/<id>.mdx`. The **frontmatter** holds the structured
   fields; the **body** is the write-up:

   ```mdx
   ---
   title: Morning Light
   medium: Oil on canvas
   year: "2025"            # quote the year so it stays a string
   dimensions: 60 × 90 cm  # optional
   image: /images/morning-light.jpg
   alt: A sunlit landscape in warm tones
   order: 7                # optional — controls grid / prev-next order
   ---

   The write-up goes here, in the artist's own voice. Multiple paragraphs,

   > pull-quotes,

   and supporting images are all supported.
   ```

| Frontmatter field | Required | Notes |
| --- | --- | --- |
| `title`, `medium`, `alt` | yes | Plain text. |
| `year` | yes | Quote it (`"2025"`) so YAML keeps it a string. |
| `image` | yes | Path to the **main** image, absolute from `public` (starts with `/`). |
| `dimensions` | no | Free text, e.g. `60 × 90 cm`. |
| `order` | no | Lower numbers come first; pieces without it sort last. |

A missing required field fails the build with a clear message.

3. Replace the placeholder copy in [`src/app/page.tsx`](src/app/page.tsx) and
   [`src/app/about/page.tsx`](src/app/about/page.tsx) with real text.

Every file in `public/images/` is currently a **placeholder SVG**, one per piece,
named after the MDX id (`roses.mdx` → `/images/roses.svg`). To drop in the real
artwork, add the photo to `public/images/` and point the `image:` field at it —
then update that piece's `alt:` text, which currently just says "placeholder".
The home hero ([`src/app/page.tsx`](src/app/page.tsx)) and the About page image
([`src/app/about/page.tsx`](src/app/about/page.tsx)) reference their images
directly and need the same treatment.

### Adding supporting images to a write-up

A write-up can include extra images that support the main piece — detail crops,
work-in-progress shots, reference photos. **Where the files go:** the same
[`public/images/`](public/images) folder as the main image (subfolders are fine,
e.g. `public/images/piece-7/detail.jpg`).

**How to reference them in the MDX** — paths are written **absolute from
`public`**, so a file at `public/images/foo.jpg` is referenced as `/images/foo.jpg`
(do not include `public` in the path). Two ways:

- **`<Figure>`** (recommended) — a captioned image. Like every image on the site,
  it fits the screen and is click-to-zoom:

  ```mdx
  <Figure
    src="/images/piece-7/detail.jpg"
    alt="Detail of the lower-left corner"
    caption="The build-up of texture in the lower-left corner."
  />
  ```

- **Plain markdown image** — no caption, also click-to-zoom:

  ```mdx
  ![Detail of the lower-left corner](/images/piece-7/detail.jpg)
  ```

The syntax above is all you need — the existing files in
[`content/portfolio/`](content/portfolio) are working examples. The styling of
headings, quotes, links, lists and images is defined in
[`src/components/mdx.tsx`](src/components/mdx.tsx).

## Deployment

Deployment to Firebase Hosting is automated with GitHub Actions:

- **On push to `main`** — [`firebase-hosting-merge.yml`](.github/workflows/firebase-hosting-merge.yml) builds the site and deploys to the live channel.
- **On pull request** — [`firebase-hosting-pull-request.yml`](.github/workflows/firebase-hosting-pull-request.yml) builds the site and deploys to a temporary preview channel.

Both workflows run `npm ci && npm run build` and upload the static `out/` directory. The Firebase project and service-account credential are configured via the `FIREBASE_SERVICE_ACCOUNT_RINNETTE` repository secret.

To deploy manually:

```bash
npm run build
firebase deploy --only hosting
```
